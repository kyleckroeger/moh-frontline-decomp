# game-code

Agent working notes, kept as written; dated claims may be out of date.


On 2026-10-06, bstimer.cpp became the first verified game unit (commit 0453465, 13.38%). The game uses MWCC GC>=1.3 (1.3.2 is used; 1.2.5n is wrong), -O4,p with scheduling on, -use_lmw_stmw on, -Cpp_exceptions on, and -inline auto (NOT deferred, so source order equals emission order). Templates are in scratch/game/tmpl_<ver>.json.

Method: use the Rising Sun reconstruction (../moh-rising-sun, src/script/*.cpp etc.; ProDG, CC0) for structure and names. Its helpers are often inlined as static functions in Frontline. Remaining diffs come from register allocation (declaration order; brute-force small permutations), store order, the case list in a switch, and extern object sizes (small-data addressing).

Harness: scratch/game/try.sh <src> <mangled func> <start> <end> [ver] prints real instruction diffs (relocation placeholders filtered). port_unit.py now places extab/extabindex. docs/Game.md has the details.

Shared-name candidates with RS reconstructions: bsmachin.cpp (~5.5 KB done in RS) and propdat.cpp (~4.1 KB). About 153 KB of Frontline functions share names with RS functions. Related: [[runtime-libraries]], [[frontline-decomp-setup]]

bsmachin.cpp WIP (2026-10-06, not committed): scratch/game/nextstate_best2.cpp holds the full candidate. 53 of 55 functions match, including all opcodes, thread functions and the 16 property readers. Those readers are generated by scratch/game/gen_propdata.py from the jump tables; fixed-point fields are `field / 16.0f`. Two functions are stuck:
- NEXTSTATE: 58 normalized diff lines. It is scheduling plus a swap between the nextState and index registers. Declaration-order hill climbing (scratch/game/climb_nextstate.py) and flag variants did not help.
- BSInitMachine: 3 instructions; the zero register is coalesced with i (target) instead of the offset induction variable (mine).
Fast harness: scratch/game/fast.py, about 0.4 s per compile, normalizes relocations and branch targets (<T>), so a 0 score can still hide a wrong branch destination; reconstruct.py is the real check. GC 1.3 through 2.7 all give identical code; 3.0 differs.

propdat.cpp EndianSwap model (2026-10-06, scratch/game/endian_all6.cpp; 15 of 17 match). Every statement is `ChangeEndian(value.fieldNN)` as in Rising Sun. The overloads are:
- non-template `ChangeEndian(short&)`, and `ChangeEndian(int&)` with an explicitly unrolled two-pair byte swap (a loop body moves the scheduling splits);
- `template<T> ChangeEndian(T&)` that delegates through `int*`, used for pointers and unsigned 32-bit values (depth 2);
- `ChangeEndian(float&)` that calls `EndianSwap(float&, bool)` (weak in Frontline), which delegates through `int*` (depth 3).
Stack slots group by inline depth (deepest at the bottom) and follow source order within a group, with shorts last; scratch/game/endian_model.py infers field types from target slots. Some int swaps show "split" schedules; this is a per-function limit (not file-global, not compiler-version, not the depth of the inline chain) that local references toggle on or off. BPDLight (6) and BPDLightVolume (4) remain off for that reason. fast.py now retries compiles because wibo fails spuriously under parallel load (9999 scores).

Profile update (2026-10-06, from propdat): the game also needs `-fp_contract on` (fused fmadds/fnmsub) and `-str reuse,readonly` (string literals in .rodata). bstimer and bsmachin are unchanged under both; the template is scratch/game/tmpl_fpc_ro.json. Other propdat findings:
- non-`inline` templates (`offsetPtr<T>`) are instantiated at the end of the unit and never auto-inlined;
- `CVector3` behaves as 8-byte aligned (stack slot and lfd copies);
- `dwi::dwi_prime_list[27]` (SGI hash primes) is a header static that leads .rodata;
- the indexed-vs-pointer loop form changes base-address CSE.

Facts established:
- Inline temporaries group by inline depth, in source order within a depth (probe: scratch/game/slot_probe.py).
- CVector3 has a user copy constructor that copies two doublewords; `CVector3 delta(position); delta -= start; delta.Length()` matches.
- Helpers: permute.py (ANCHOR env scopes it to one function) and sbs.py (side-by-side).

EA library rules (2026-10-07). Units in src/ea are `--category reconstructed_game` (docs/Game.md); src/msl is `restored_library`. 89 units were mislabeled until cf30932. The best way to find easy targets is the original file records' .text starts: `scratch/records.py` lists uncovered files by size, `scratch/dumprec.py` disassembles them, and `scratch/check_bounds.py` must print nothing (no unit may swallow another file's start). Sound-library .c files are compiled as C++ (`scratch/lib/tmpl_snd_cpp.json`, like_snd_c.json). Use `set -o pipefail` in port and commit chains, and keep `git commit` in the SAME `&&` chain as reconstruct/tests (a commit on a later line ran after a failed build once). `scratch/records.py N` lists the N smallest uncovered files (default 60). A fragment that calls a file-local function must declare it non-static (port_unit then records a local external). Units whose .sbss starts at a 4-mod-8 address cannot verify (CW aligns .sbss to 8, GNU ld pads).

Fragments (2026-10-07): bsmachin.cpp landed as a 36-function fragment (aba85f0) between the two stuck functions NEXTSTATE and BSInitMachine; the unit defines all the file data. A second fragment after a stuck function fails when both need the same pooled .sdata2 constant. port_unit ties the source basename to the original file record.

Correction (2026-10-14): a `stfd f31 / psq_st f31` prologue (objdump misdecodes the second FPR's psq_st as `xscmpgtdp`) is the normal GC 1.3.2 output for any function that saves FPRs. It is not a paired-single blocker. Only real ps_* arithmetic (e.g. the matrix sinit) is special. Two more lessons:
- fast.py normalizes pooled-constant values, so read the real constant from .sdata2 before landing.
- Locals of an inline helper take stack slots in source order (lower address first), while a function's own locals take them in reverse declaration order. Use this to tell which shape the original had.

Register-numbering lessons (2026-10-17):
- `unsigned int` and `unsigned long` (both 32-bit) give DIFFERENT register allocation in CW. When hand variants plateau on register numbering, try int/long type swaps of params and locals early (CheckIfValidPassword's last 36 lines were `Reflect(unsigned int value, ...)`).
- Start the permuter (scratch/perm/autoperm.py) sooner. It found that type swap in 2 minutes after about 15 hand variants had failed. Expand inline-member logic into the body first, because the permuter only mutates the function body.
- Deferred-inline files: the auto-inline limit is about 30 call statements, measured on the simplified IR. Casts and explicit compares do not change it, inlined-helper expansions do not count, and `level=N` has no effect.
- If a loop counter takes the callee-saved register that `this` (or another long-lived value) has in the original, move the loop into a small inline member helper with its own `int i`. The CShellMenu constructor went from 330 lines off to 0 this way (InitButtons/ResetPlayers, 2026-10-17).
- Every extern object a function addresses needs a view at least its real size, or CW uses SDA addressing (`addi rX,r13`) instead of lis/addi (CDualConfig, CShellMenu 0x19dc).

Lessons 2026-10-17 (UserInterface.cpp): CW unswitches loops, so invariants hoisted above an `if` that selects between two loop copies mean one source loop with the `if` inside. Unroll factors follow IR size; per-axis locals can change x8 into x4. Register numbering for locals follows declaration order (declaring `other`/`i`/`type` before `player` moved them). Sized extern classes avoid small-data addressing for big globals.
